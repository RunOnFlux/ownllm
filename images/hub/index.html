API keys

Demo key

The key on this page is public and shared. It is limited per hub instance to a handful of requests per minute and one request at a time. Good for trying models and for small scripts, not for an app.

Your own key

Keys are issued per person or project with higher limits, and can be revoked individually. Ask in the Flux community channels or open an issue on GitHub.

Run your own

Everything here is open source and deploys from one command. Run the same endpoint under your own Flux account with the models you choose: RunOnFlux/ownllm.

How it works

Pools of nodes

Each model runs in a pool: an application on the Flux network with many instances, each a CPU node somewhere in the world running the model server. Instances migrate and scale without anyone reconfiguring clients.

One endpoint

The hub maps the model in your request to its pool, discovers that pool's instances from the Flux API, and sends each request to the least busy healthy one. Sessions stay on the same instance while it is free, so long conversations keep their prompt cache.

Stateless keys

A key is a signed name. Every hub instance verifies it with no shared database, which is the only kind of state a multi-instance application on a decentralized network can have. Limits and usage are enforced per key.

No GPUs

These are CPU nodes. Small and mixture-of-experts models with few active parameters are what run well here: that is why the roster looks the way it does. The research notes cover what was measured.
